# Accessibility and internationalization

`check.py` measures both. The `a11y` and `states` gates come from a real keyboard and pointer
run over the rendered window (`render.py --interact` → `interaction.json`). The `i18n` gate
reads the QML.

## Accessibility

- **Names.**
  - Template controls expose the right `Accessible.role` and use `text` as the name, and
    text fields use `placeholderText`.
  - Set `Accessible.name` when the visible text is not a good name: icon-only buttons,
    sliders, combo boxes, spin boxes, progress bars, badges ("3 aktif alarm") and gauges
    ("Tank A, yüzde 72").
  - The gate fails controls with no name.
- **Information that is not a control.** Give it `Accessible.role` (`StaticText`,
  `ProgressBar`, `ListItem`, `Chart`, `Pane`, `Heading`) plus `Accessible.name`. Mark
  decorative glyphs with `Accessible.ignored: true`.
- **Keyboard.**
  - Every enabled control is a Tab stop (`focusPolicy: Qt.StrongFocus`).
  - The Tab order follows reading order: declare items in that order, or set
    `KeyNavigation.tab`.
  - Each control takes one Tab stop only. The kit's SpinBox forwards to its value field; a
    custom control with an inner `TextInput` must do the same.
  - The gate presses Tab until focus cycles and fails controls it never reaches.
- **Visible focus.** Draw a ring on `visualFocus` (the kit's `FocusRing`). The gate fails a
  control whose pixels do not change when it takes keyboard focus.
- **Pressed and hover.** Pressed must be visible, because touch users get no other feedback.
  Hover is checked on desktop only.
- **Touch targets.** On kiosk, HMI and mobile screens a target is at least 44×44 px, even when
  the drawing is smaller: enlarge the control, not the drawing. The gate warns below 44 px on
  embedded profiles.
- **No `MouseArea` buttons.** Anything clickable is a Template control; the gate warns about
  `MouseArea`s outside controls.
- **Contrast.** Keep the design's colors. If body text is below 4.5:1 against its
  background, mention it in the README instead of silently changing it.
- **High contrast.** Qt 6.10+ follows the OS high-contrast setting in built-in styles; custom
  Theme colors do not. Offer a high-contrast palette when the product needs it.

## Internationalization

- **Wrap every user-visible string in `qsTr()`:**
  - `text`, `title`, `placeholderText`, `Accessible.name`, `ToolTip.text`;
  - string-list models such as `model: [qsTr("Gün"), qsTr("Hafta")]`.

  The gate fails literals in production mode. Data is not translated in QML: mock data files
  and `ListElement` values are exempt.
- **Keep sentences whole:** `qsTr("Operatör: %1").arg(name)`, never `"Operatör: " + name`.
  Use `qsTr("%n ürün", "", count)` for plurals.
- **Translation files.** Scaffolded projects load `i18n/app_<locale>.qm` for the system
  locale; `APP_LANG=en` overrides it.

  ```bash
  pyside6-lupdate qml/App/*.qml qml/App/Controls/*.qml -ts i18n/app_en.ts   # extract
  # translate in Qt Linguist (pyside6-linguist), then compile:
  pyside6-lrelease i18n/app_en.ts -qm i18n/app_en.qm
  python <skill>/scripts/render.py . --size W H --lang en --out render_en.png  # check the layout
  ```
- **Numbers and dates.** Use the app locale for both:
  - `Number(v).toLocaleString(Qt.locale("tr_TR"), "f", 1)`
  - `Qt.formatDateTime(d, "dddd, dd.MM.yyyy")`
- **Longer strings.** Layouts must survive strings 30–40 % longer (German). Avoid fixed widths
  around text and elide only where space is truly fixed. Render with `--lang` to check.
- **Right to left.** On the root, set `LayoutMirroring.enabled: Qt.application.layoutDirection
  === Qt.RightToLeft` and `LayoutMirroring.childrenInherit: true`.
- **Turkish.** Casing, ı/İ and the decimal comma are covered in typography.md.
  `Font.AllUppercase` turns i into I, not İ.
